# Support

## User questions and reproducible problems

Use GitHub Issues for installation failures, reproducible software defects,
scientific validation results, and feature proposals. Select the issue form
that matches the request and include the exact DiffractScout version, operating
system, input type, settings, and relevant output diagnostics.

Public issues must not contain API keys, unpublished proprietary data,
restricted CIF files, personal information, or confidential experimental
metadata. A minimal synthetic reproducer is preferred.

## Scientific discrepancies

Use the scientific-validation issue form and report:

- the independent equation, software, standard, or dataset;
- all conventions, units, versions, and tolerances;
- expected and observed values;
- whether the difference appears numerical, conventional, methodological, or
  unresolved.

The maintainer records confirmed defects, convention differences, and known
limitations separately. Missing evidence remains unresolved rather than being
classified by assumption.

## Security and sensitive reports

Follow `SECURITY.md`. Do not open a public issue for a credential leak or a
vulnerability that would expose user data before a coordinated fix is
available.

## Response and maintenance scope

Support is provided on a best-effort basis through public project records. The
project does not provide emergency experimental decisions, certified phase
identification, instrument calibration, or guaranteed interpretation of
unpublished data. Supported behavior is defined by the latest documented
release and `docs/SCIENTIFIC_CONTRACTS.md`.
