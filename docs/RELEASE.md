# Release procedure

## 1. Prepare the release branch

1. Confirm that the working tree contains only intended changes.
2. Update `CHANGELOG.md`.
3. Set the same version in:
   - `pyproject.toml`;
   - `src/diffractscout/__init__.py`;
   - `CITATION.cff`.
4. Update screenshots, validation counts, paper statements, and source-lineage notes when affected.

## 2. Run local preflight

```bash
python scripts/check_release.py
```

This checks required files, version consistency, bibliography keys, compilation, tests, the offline demo, manifest verification, and wheel creation.

Additional GUI smoke check on Linux:

```bash
xvfb-run -a python -c \
  "from diffractscout.gui import create_app; app=create_app(); app.update(); app.destroy()"
```

Inspect the generated wheel:

```bash
python -m zipfile -l dist/diffractscout-*.whl
```

## 3. Verify a clean installation

Create a new environment outside the repository and install the wheel:

```bash
python -m venv /tmp/diffractscout-wheel-test
/tmp/diffractscout-wheel-test/bin/python -m pip install dist/diffractscout-*.whl
/tmp/diffractscout-wheel-test/bin/python -m diffractscout demo -o /tmp/diffractscout-demo
/tmp/diffractscout-wheel-test/bin/python -m diffractscout verify /tmp/diffractscout-demo
```

Windows paths should use the environment's `Scripts\python.exe`.

## 4. Review scientific and legal material

Review:

- `docs/SCIENTIFIC_CONTRACTS.md`;
- `docs/SOURCE_LINEAGE.md`;
- `docs/VALIDATION.md`;
- dependency licenses;
- `NOTICE.md`;
- `AUTHORS.md`;
- `paper/paper.md` and its AI disclosure;
- author, affiliation, funding, acknowledgements, and archive metadata.

The human release owner should inspect representative CSV/XLSX/provenance output and confirm that diagnostic errors are visible and scientific boundaries remain accurate.

## 5. Build and inspect the paper

The exact JOSS draft is generated by `.github/workflows/draft-pdf.yml`. When Docker is available locally:

```bash
bash scripts/build_paper.sh
```

Render and inspect the PDF:

```bash
python /home/oai/skills/pdfs/scripts/render_pdf.py paper/paper.pdf \
  --out_dir /tmp/diffractscout-paper-render --dpi 200
```

## 6. Publish

After CI passes on the release commit:

1. merge the release pull request;
2. delete the merged feature branch after confirming the PR head SHA is represented in the default branch;
3. create an annotated tag, for example `v0.2.0`;
4. push the tag;
5. create GitHub release notes from `CHANGELOG.md`;
6. attach distribution files and checksums when appropriate;
7. archive the tagged release with Zenodo or an equivalent service;
8. add the archive DOI to `CITATION.cff`, `paper/paper.md`, and the GitHub release;
9. rebuild the JOSS draft and rerun release checks if metadata changed.

Remote branch deletion is a separate destructive action. Delete only branches that are merged, have no unique unreviewed commits, are not protected/default/current branches, and have been explicitly selected for cleanup.
